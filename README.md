# Каталог плитки «Алмалы-Керамик» + QR-коды

Публичная витрина: у каждой модели своя страница с галереей и свой QR-код.

Фотографии и состав карточек задаются на дилерском портале
([almaly-dealers](https://github.com/almaliceramicc/almaly-dealers)) и сами приходят сюда.
Обратно эта витрина ничего не отправляет.

- Владелец поменял фото на портале (загрузка, удаление, порядок, обложка) —
  workflow «Зеркало витрины» записывает `photos/<АРТИКУЛ>/` в том же порядке.
  Первое фото становится обложкой. Этот push запускает пересборку сайта и QR-кодов,
  обычно за несколько минут.
- Владелец нажал на портале «Убрать карточку» — артикул пропадает из `arts.txt`
  и здесь. Папка `photos/<АРТИКУЛ>/` этой модели очищается.
- Ночной workflow «Пересборка каталога» по-прежнему скачивает Google-таблицу
  (`sync_sheet.py`) и собирает сайт (`build.py`). Список `arts.txt` и присланные
  фото он не переписывает, поэтому удалённая карточка и новые снимки после ночи
  остаются как на портале.
- Обновление только остатков на портале витрину не запускает.

Редактор на этой витрине (страница ниже и `./edit.sh`) по-прежнему открывается.
Для обычной работы он не нужен: следующая правка той же модели на портале
заменит фото, а следующее изменение списка карточек заново запишет `arts.txt`.

## Редактор медиа онлайн (с любого устройства)

https://almaliceramicc.github.io/almaly-tiles/admin.html — вход по GitHub-токену
(fine-grained, репозиторий `almaly-tiles`, Repository permissions → Contents: Read and write).
Токен сохраняется в браузере. Загрузка, удаление, порядок и обложка пишутся коммитом в `photos/`,
после чего GitHub Action пересобирает сайт и QR-коды (1–2 минуты). Фото при загрузке
автоматически ужимаются до 1600 px.

Каталог сам обновляется из Google-таблицы каждую ночь (workflow «Пересборка каталога»,
он же запускается кнопкой Run workflow вручную). Ночь обновляет цены наличия из таблицы,
но не возвращает карточки, которые убрали на портале.

## Редактор медиа на Mac

   ./edit.sh

Откроется http://localhost:8787 — список всех моделей: перетаскивание файлов,
удаление, стрелки для порядка, ★ — сделать обложкой, кнопка «Опубликовать изменения»
пересобирает сайт и выкладывает его. Файлы правятся прямо в `photos/<АРТИКУЛ>/`.

## Как добавить фото вручную

Обычный путь — редактор на дилерском портале. Запасной, если портал недоступен:

1. Положить файлы в `photos/<АРТИКУЛ>/` (папки уже созданы для всех рабочих артикулов).
   Порядок — по имени файла: `01.jpg`, `02.jpg`, ... Первое фото становится обложкой.
2. Собрать сайт:

   python3 build.py

3. Выложить обновление (если сайт уже на GitHub Pages):

   ./publish.sh

Такие файлы живут, пока ту же модель в следующий раз не сохранят на портале:
зеркало заменит папку снимками портала.

## Как обновить список плиток из таблицы

Состав карточек (какие артикулы показывать) теперь ведётся на портале, в `arts.txt`.
Команда ниже только освежает выгрузку таблицы и собирает сайт. Строки, которых
нет в `arts.txt`, в каталог не попадут.

   python3 sync_sheet.py && python3 build.py

## Что где

- `data/*.csv` — выгрузка листов таблицы (60×60 и 60×120), её пишет ночной запуск
- `arts.txt` — какие артикулы показывать. Копия списка с дилерского портала.
  Ночная пересборка этот файл не трогает
- `photos/<АРТИКУЛ>/` — исходные фото. Для моделей, которые правили на портале,
  здесь те же кадры и в том же порядке (первое — обложка)
- `docs/` — готовый сайт: `index.html` (каталог), `tile.html?a=АРТИКУЛ`, `print.html` (лист QR на печать)
- `editor.py` + `editor.html` — редактор медиа (`./edit.sh`)
- `qr/<АРТИКУЛ>.png` — QR-коды 1000×1000 для печати и наклеек.
- `config.json` — адрес сайта. QR-коды строятся из него: поменял адрес — перезапусти `build.py`

Остатки складов на сайт намеренно не выводятся.

Секрет для приёма правок с портала хранится не здесь, а в репозитории
`almaly-dealers` под именем `TILES_TOKEN`. Как его создать — в README портала,
раздел «Зеркало витрины».
